# Fit statement — Digital Commons EDIC (one pager)

**Date:** 2026-09-20 (EuropAI M3 / framing M4–M6)  
**Relationship owners (WP4):** BZK + ICTU  
**Asset class:** Code stewardship (T4.3) — source, contribution rules, maintenance envelope  
**Track:** stewardship track of route 3
([route-citiverse-first.md](route-citiverse-first.md)) — pack in M4, handover
at MS21. GovChat-NL stays here, not in CitiVERSE.  
**Fallback from M12:** OS2 community

## What we offer

A working **open implementation** of the governed agent layer plus PoC engines,
with an explicit **GovChat-NL** front-door integration (beleidskompas). This is
the asset class that answers “who maintains this in 2030?”.

## What we need

Commons acceptance of the repository (licence, contribution, security process)
and a documented maintenance cost envelope. GovChat-NL is **not** filed as a
CitiVERSE city app.

- `nldt/services/`, `nldt/agents/`, `poc/pipeline/` and sibling PoC engines
- GovChat-NL beleidskompas integration
  ([14-beleidskompas-integration.md](../14-beleidskompas-integration.md))

Secondary / ALT-EDIC only if multilingual legal text (NormCard quotes,
plain-language explanation) is packaged as language assets later.

## Proposed acceptance

1. SPDX / EUPL-1.2 on nLDT code; documented exception where a dependency
   differs (GovChat-NL Open WebUI licence).
2. CONTRIBUTING + security disclosure + named CODEOWNERS.
3. Maintenance envelope: what stays mock, what is a production service, FTE.
4. Clean IP statement before MS21.

## Reciprocity

Digital Commons gets a maintained digital common it did not have to start.
EuropAI gets a 2030 owner for code that IMPACTS and CitiVERSE will keep
calling.
